**DVC** signifie **Data Version Control**.

C’est un outil utilisé en **Data Science / Machine Learning** pour versionner et gérer les **datasets, modèles et pipelines**, un peu comme **Git**, mais adapté aux fichiers de données volumineux.

### Exemple simple

Avec Git, tu versions ton code :

```text
Git
 ├── train.py
 ├── model.py
 └── README.md
```

Avec DVC, tu peux versionner les données et modèles :

```text
Git + DVC
 ├── code/
 │    └── train.py
 │
 ├── data/
 │    └── dataset.csv       ← géré par DVC
 │
 └── models/
      └── model.pkl         ← géré par DVC
```

### Pourquoi utiliser DVC ?

Supposons que tu entraînes un modèle aujourd'hui avec :

```text
dataset_v1.csv → modèle_v1
```

Puis tu modifies le dataset :

```text
dataset_v2.csv → modèle_v2
```

DVC permet de garder la trace de ces versions et de revenir facilement à une ancienne version.

Il est particulièrement utile pour :

- 📊 **Versionner les datasets**
    
- 🤖 **Versionner les modèles ML**
    
- 🔄 Reproduire les expériences
    
- 🔗 Relier une version du code à une version précise des données
    
- ☁️ Stocker les données sur un stockage distant
    
- 🧪 Reproduire un pipeline ML
    

### DVC vs Git

|Git|DVC|
|---|---|
|Code|Datasets|
|Fichiers texte|Gros fichiers|
|`git commit`|`dvc add`|
|GitHub|DVC + stockage distant|
|Versionne le code|Versionne les données/modèles|

Par exemple :

```bash
git add train.py
git commit -m "training model"
```

et pour le dataset :

```bash
dvc add data/dataset.csv
```

Puis :

```bash
git add data/dataset.csv.dvc
git commit -m "version dataset"
```

👉 **En résumé : DVC = Git pour les données et les expériences ML**, avec des fonctionnalités supplémentaires pour reproduire les pipelines.

Si tu travailles sur un projet **ML/MLOps**, DVC est donc très utile.
